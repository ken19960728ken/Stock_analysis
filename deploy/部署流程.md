# Cloud Run 雙服務部署流程

本文件記錄從零開始將台灣股市量化交易系統部署到 GCP Cloud Run 的完整流程。

## 環境資訊

| 項目 | 版本 |
|------|------|
| 作業系統 | macOS Ventura 13.5 (Build 22G74) |
| CPU 架構 | Apple Silicon arm64 (M 系列) |
| Homebrew | 5.1.0 |
| Python (系統) | 3.13.9 (Anaconda) |
| Python (gcloud 用) | 3.10.16 (`/opt/homebrew/opt/python@3.10`) |
| Docker Desktop | 4.30.0 (Docker Engine 26.1.1) |
| Google Cloud SDK | 560.0.0 |
| GCP 專案 | `stock-analysis-tw` |
| GCP 區域 | `asia-east1` (台灣) |
| Cloud Run 目標平台 | `linux/amd64` |

> **重要**：Apple Silicon Mac build 出來的映像預設是 `arm64`，Cloud Run 需要 `linux/amd64`，必須用 `docker buildx build --platform linux/amd64` 交叉建置。

## Step 0：前置軟體安裝

### 0-1. 安裝 Homebrew（如果沒有）

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

### 0-2. 安裝 Python 3.10（gcloud 需要）

```bash
brew install python@3.10
```

### 0-3. 安裝 Google Cloud SDK

Homebrew 安裝在 macOS 13 會因 Python 版本衝突失敗，改用官方 tarball：

```bash
# 下載 Apple Silicon 版本
cd ~/Downloads
curl -O https://dl.google.com/dl/cloudsdk/channels/rapid/downloads/google-cloud-cli-darwin-arm.tar.gz

# 解壓到 home 目錄
tar -xf google-cloud-cli-darwin-arm.tar.gz -C ~/

# 指定用 Python 3.10 安裝（避免版本衝突）
CLOUDSDK_PYTHON=/opt/homebrew/opt/python@3.10/libexec/bin/python3 \
    ~/google-cloud-sdk/install.sh --quiet --path-update=true --rc-path=$HOME/.zshrc

# 寫入環境變數，確保每次都用 Python 3.10
echo 'export CLOUDSDK_PYTHON=/opt/homebrew/opt/python@3.10/libexec/bin/python3' >> ~/.zshrc

# 重新載入 shell
source ~/.zshrc

# 驗證
gcloud --version
# 預期輸出: Google Cloud SDK 560.0.0
```

### 0-4. 安裝 Docker Desktop

Docker Desktop 4.64+ 不支援 macOS 13 (Ventura)，需安裝 4.30（最後支援版本）：

```bash
# 下載 Docker Desktop 4.30 (Apple Silicon)
curl -L -o ~/Downloads/Docker-4.30.0.dmg \
    "https://desktop.docker.com/mac/main/arm64/149282/Docker.dmg"

# 掛載 DMG
hdiutil attach ~/Downloads/Docker-4.30.0.dmg -nobrowse

# 複製到 Applications
cp -R "/Volumes/Docker/Docker.app" /Applications/

# 卸載 DMG
hdiutil detach /Volumes/Docker

# 啟動 Docker Desktop（第一次需同意條款）
open /Applications/Docker.app

# 等待啟動完成後驗證
docker --version
# 預期輸出: Docker version 26.1.1, build 4cf5afa
```

> 如果 macOS >= 14 (Sonoma)，可直接 `brew install --cask docker` 安裝最新版。

## Step 1：GCP 專案設定

### 1-1. 登入 Google 帳號

```bash
gcloud auth login
# 會開啟瀏覽器，登入你的 Google 帳號
```

### 1-2. 建立新專案

```bash
gcloud projects create stock-analysis-tw --name="Stock Analysis"
gcloud config set project stock-analysis-tw
```

### 1-3. 綁定帳單帳戶

```bash
# 列出帳單帳戶
gcloud billing accounts list

# 綁定（替換 ACCOUNT_ID 為你的帳單帳戶 ID）
gcloud billing projects link stock-analysis-tw --billing-account=ACCOUNT_ID
```

### 1-4. 啟用 API + 建立 Artifact Registry

```bash
export GCP_PROJECT_ID="stock-analysis-tw"
export GCP_REGION="asia-east1"

bash deploy/setup.sh
```

這會：
- 啟用 Cloud Run、Cloud Scheduler、Artifact Registry、Cloud Build API
- 建立 Docker 映像倉庫 `stock-analysis`
- 設定 Docker 認證

## Step 2：設定環境變數

建立 `.env.deploy`（**不要 commit**）：

```bash
cat > .env.deploy << 'EOF'
export GCP_PROJECT_ID="stock-analysis-tw"
export GCP_REGION="asia-east1"
EOF
```

後續部署前載入：

```bash
# 載入專案 .env（含 SUPABASE_URL, FINMIND_TOKEN 等）
export $(grep -v '^#' .env | grep '=' | xargs)

# 載入 GCP 設定
source .env.deploy
```

### 需要的環境變數

| 變數 | 必要 | 說明 |
|------|------|------|
| `SUPABASE_URL` | ✅ | PostgreSQL 連線字串 |
| `FINMIND_TOKEN` | 選填 | FinMind API Token（提高限速） |
| `EMAIL_SENDER` | 選填 | Gmail 寄件人 |
| `EMAIL_APP_PASSWORD` | 選填 | Gmail 應用程式密碼 |
| `EMAIL_RECIPIENTS` | 選填 | 收件人（逗號分隔） |
| `FRED_API_KEY` | 選填 | FRED 經濟指標 API Key |

## Step 3：部署 Pipeline（Cloud Run Job）

```bash
bash deploy/deploy-pipeline.sh
```

腳本會：
1. 用 `docker buildx build --platform linux/amd64` 交叉建置映像
2. 推送至 Artifact Registry
3. 產生 YAML 環境變數檔（自動處理特殊字元）
4. 建立 / 更新 Cloud Run Job（512Mi, 1 CPU, timeout 1hr）

### 手動觸發測試

```bash
# 執行一次 Job
gcloud run jobs execute stock-pipeline \
    --region=asia-east1 --project=stock-analysis-tw

# 查看執行紀錄
gcloud run jobs executions list \
    --job=stock-pipeline \
    --region=asia-east1 --project=stock-analysis-tw

# 即時看 log
gcloud logging read \
    "resource.type=cloud_run_job AND resource.labels.job_name=stock-pipeline" \
    --project=stock-analysis-tw --limit=50 --format="value(textPayload)"
```

## Step 4：部署 Analysis（Cloud Run Service）

```bash
bash deploy/deploy-analysis.sh
```

腳本會：
1. 交叉建置 amd64 映像 + 推送
2. 部署 Cloud Run Service（1Gi, 0-2 instances, 公開存取）
3. 印出 Service URL

部署完成後瀏覽器打開 Service URL 即可使用：

```
服務 URL: https://stock-analysis-390389877301.asia-east1.run.app
```

## Step 5：設定每日排程

```bash
bash deploy/setup-scheduler.sh
```

排程設定：
- **Cron**: `0 9 * * 1-5` UTC = **17:00 台北時間，週一至五**
- **動作**: 自動觸發 `stock-pipeline` Job

### 手動操作排程

```bash
# 手動觸發
gcloud scheduler jobs run trigger-stock-pipeline \
    --location=asia-east1 --project=stock-analysis-tw

# 暫停排程
gcloud scheduler jobs pause trigger-stock-pipeline \
    --location=asia-east1 --project=stock-analysis-tw

# 恢復排程
gcloud scheduler jobs resume trigger-stock-pipeline \
    --location=asia-east1 --project=stock-analysis-tw
```

## 日常維護

### 更新程式碼後重新部署

```bash
# 載入環境變數
export $(grep -v '^#' .env | grep '=' | xargs)
source .env.deploy

# 重新部署（會自動重建映像 + 推送 + 更新服務）
bash deploy/deploy-pipeline.sh    # 更新 Pipeline Job
bash deploy/deploy-analysis.sh    # 更新 Analysis Service
```

### 查看 Log

```bash
# Analysis Service log
gcloud run services logs read stock-analysis \
    --region=asia-east1 --project=stock-analysis-tw --limit=50

# Pipeline Job 某次執行的 log
gcloud logging read \
    "resource.type=cloud_run_job AND resource.labels.job_name=stock-pipeline" \
    --project=stock-analysis-tw --limit=50 --format="value(textPayload)"

# Pipeline Job 執行歷史
gcloud run jobs executions list --job=stock-pipeline \
    --region=asia-east1 --project=stock-analysis-tw
```

### 刪除服務（如需清理）

```bash
# 刪除排程
gcloud scheduler jobs delete trigger-stock-pipeline \
    --location=asia-east1 --project=stock-analysis-tw

# 刪除 Job
gcloud run jobs delete stock-pipeline \
    --region=asia-east1 --project=stock-analysis-tw

# 刪除 Service
gcloud run services delete stock-analysis \
    --region=asia-east1 --project=stock-analysis-tw

# 刪除映像倉庫
gcloud artifacts repositories delete stock-analysis \
    --location=asia-east1 --project=stock-analysis-tw
```

## 費用估算

| 服務 | 預估月費 (USD) |
|------|---------------|
| Cloud Run Job（每天 1 次 ~10min） | ~$1-2 |
| Cloud Run Service（idle 縮到 0） | ~$0（沒人存取不收費） |
| Artifact Registry（映像儲存） | ~$0.5 |
| Cloud Scheduler | 免費（3 個以內） |
| **合計** | **~$2-3/月** |

> `min-instances=0` 表示沒人存取時 Service 縮到 0，首次打開有 10-20 秒冷啟動。
> 如需即時回應，改為 `min-instances=1`（月費增加 ~$10-15）。

## 踩坑紀錄

### 1. gcloud 安裝 Python 版本衝突

**問題**: `brew install --cask google-cloud-sdk` 在 macOS 13 失敗，報 `python path does not exist`。
**原因**: Homebrew 的 gcloud cask 預設找 `python@3.13`，但 Homebrew 在 macOS 13 沒安裝它。
**解法**: 用官方 tarball + 指定 `CLOUDSDK_PYTHON=/opt/homebrew/opt/python@3.10/libexec/bin/python3`。

### 2. Docker Desktop 版本不相容

**問題**: `brew install --cask docker` 報 `does not run on macOS versions older than Sonoma`。
**原因**: Docker Desktop 4.64+ 要求 macOS 14 (Sonoma) 以上。
**解法**: 手動下載 Docker Desktop 4.30（build 149282），這是最後支援 Ventura 的版本。

### 3. Cloud Run exec format error

**問題**: 部署後容器啟動失敗，log 顯示 `exec format error`。
**原因**: Apple Silicon Mac 預設 build 出 `arm64` 映像，Cloud Run 需要 `amd64`。
**解法**: 用 `docker buildx build --platform linux/amd64` 交叉建置。

### 4. --set-env-vars 特殊字元解析錯誤

**問題**: `gcloud run jobs create --set-env-vars` 解析 email 地址的 `@` 時報 `Bad syntax for dict arg`。
**原因**: gcloud 把 `@` 和 `,` 視為分隔符。
**解法**: 改用 `--env-vars-file` 傳入 YAML 檔，值用雙引號包裹。
