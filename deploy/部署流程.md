# Cloud Run 雙服務部署流程

本文件記錄從零開始將台灣股市量化交易系統部署到 GCP Cloud Run 的完整流程。

## 環境資訊

| 項目 | 版本 |
|------|------|
| 作業系統 | macOS Ventura 13.5 (Build 22G74) |
| CPU 架構 | Apple Silicon arm64 (M 系列) |
| Homebrew | 5.1.0 |
| Python (系統) | 3.13.9 (Anaconda) |
| Python (gcloud 用) | 3.10.16 (`/opt/homebrew/opt/python@3.10`) |
| Docker Desktop | 4.30.0 (Docker Engine 26.1.1) |
| Google Cloud SDK | 560.0.0 |
| GCP 專案 | `stock-analysis-tw` |
| GCP 區域 | `asia-east1` (台灣) |
| Cloud Run 目標平台 | `linux/amd64` |

> **重要**：Apple Silicon Mac build 出來的映像預設是 `arm64`，Cloud Run 需要 `linux/amd64`，必須用 `docker buildx build --platform linux/amd64` 交叉建置。

## Step 0：前置軟體安裝

### 0-1. 安裝 Homebrew（如果沒有）

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

### 0-2. 安裝 Python 3.10（gcloud 需要）

```bash
brew install python@3.10
```

### 0-3. 安裝 Google Cloud SDK

Homebrew 安裝在 macOS 13 會因 Python 版本衝突失敗，改用官方 tarball：

```bash
# 下載 Apple Silicon 版本
cd ~/Downloads
curl -O https://dl.google.com/dl/cloudsdk/channels/rapid/downloads/google-cloud-cli-darwin-arm.tar.gz

# 解壓到 home 目錄
tar -xf google-cloud-cli-darwin-arm.tar.gz -C ~/

# 指定用 Python 3.10 安裝（避免版本衝突）
CLOUDSDK_PYTHON=/opt/homebrew/opt/python@3.10/libexec/bin/python3 \
    ~/google-cloud-sdk/install.sh --quiet --path-update=true --rc-path=$HOME/.zshrc

# 寫入環境變數，確保每次都用 Python 3.10
echo 'export CLOUDSDK_PYTHON=/opt/homebrew/opt/python@3.10/libexec/bin/python3' >> ~/.zshrc

# 重新載入 shell
source ~/.zshrc

# 驗證
gcloud --version
# 預期輸出: Google Cloud SDK 560.0.0
```

### 0-4. 安裝 Docker Desktop

Docker Desktop 4.64+ 不支援 macOS 13 (Ventura)，需安裝 4.30（最後支援版本）：

```bash
# 下載 Docker Desktop 4.30 (Apple Silicon)
curl -L -o ~/Downloads/Docker-4.30.0.dmg \
    "https://desktop.docker.com/mac/main/arm64/149282/Docker.dmg"

# 掛載 DMG
hdiutil attach ~/Downloads/Docker-4.30.0.dmg -nobrowse

# 複製到 Applications
cp -R "/Volumes/Docker/Docker.app" /Applications/

# 卸載 DMG
hdiutil detach /Volumes/Docker

# 啟動 Docker Desktop（第一次需同意條款）
open /Applications/Docker.app

# 等待啟動完成後驗證
docker --version
# 預期輸出: Docker version 26.1.1, build 4cf5afa
```

> 如果 macOS >= 14 (Sonoma)，可直接 `brew install --cask docker` 安裝最新版。

## Step 1.5：建立 Secret Manager Secrets

敏感變數（資料庫密碼、API Token）存放在 GCP Secret Manager，Cloud Run 執行時自動注入為環境變數。

```bash
# 確認 .env 已設定好敏感變數（SUPABASE_URL, FINMIND_TOKEN, EMAIL_APP_PASSWORD, FRED_API_KEY）
bash deploy/setup-secrets.sh
```

腳本會：
1. 啟用 Secret Manager API
2. 從 `.env` 讀取 4 個敏感值，建立（或更新）Secret
3. 授予 default compute SA `roles/secretmanager.secretAccessor` 權限

### Secret 對照表

| Secret 名稱 | 環境變數 | 注入至 |
|---|---|---|
| `supabase-url` | `SUPABASE_URL` | Pipeline Jobs + Analysis Service |
| `finmind-token` | `FINMIND_TOKEN` | Pipeline Jobs |
| `email-app-password` | `EMAIL_APP_PASSWORD` | stock-report Job |
| `fred-api-key` | `FRED_API_KEY` | Analysis Service |

> **冪等設計**：已存在的 Secret 會新增版本而非報錯，可安全重複執行。

## Step 2：設定環境變數

建立 `.env.deploy`（**不要 commit**）：

```bash
cat > .env.deploy << 'EOF'
export GCP_PROJECT_ID="stock-analysis-tw"
export GCP_REGION="asia-east1"
EOF
```

後續部署前載入：

```bash
# 載入 GCP 設定
source .env.deploy

# 非敏感變數（如 EMAIL_SENDER, EMAIL_RECIPIENTS）需 export 供部署腳本使用
# 敏感變數已由 Secret Manager 管理，不需 export
[ -n "${EMAIL_SENDER:-}" ] || export EMAIL_SENDER="your-email@gmail.com"
[ -n "${EMAIL_RECIPIENTS:-}" ] || export EMAIL_RECIPIENTS="recipient@example.com"
```

### 環境變數分類

**由 Secret Manager 管理（敏感值）** — 部署腳本自動從 Secret Manager 讀取，不需 export：

| Secret | 環境變數 | 說明 |
|--------|---------|------|
| `supabase-url` | `SUPABASE_URL` | PostgreSQL 連線字串 |
| `finmind-token` | `FINMIND_TOKEN` | FinMind API Token |
| `email-app-password` | `EMAIL_APP_PASSWORD` | Gmail 應用程式密碼 |
| `fred-api-key` | `FRED_API_KEY` | FRED 經濟指標 API Key |

**由 YAML 環境變數檔傳入（非敏感值）** — 部署腳本自動產生：

| 變數 | 預設值 | 說明 |
|------|--------|------|
| `DB_POOL_SIZE` | `3` | SQLAlchemy 連線池大小 |
| `DB_POOL_OVERFLOW` | `2` | 連線池溢出上限 |
| `EMAIL_SENDER` | — | Gmail 寄件人地址（需 export） |
| `EMAIL_RECIPIENTS` | — | 收件人，逗號分隔（需 export） |

> **`EMAIL_PROXY` 僅限本地開發**：本地若需透過代理連線 Gmail SMTP，可在 `.env` 設 `EMAIL_PROXY=http://127.0.0.1:7890`。
> Cloud Run 容器內無 proxy，部署腳本已排除此變數，**不會帶入 Cloud Run 環境**。

> **Email 注意事項**：
> - Gmail 應用程式密碼需至 [Google 帳號安全性](https://myaccount.google.com/apppasswords) 產生
> - 三個 Email 變數（`EMAIL_SENDER`、`EMAIL_APP_PASSWORD`、`EMAIL_RECIPIENTS`）需同時設定，缺任一則靜默跳過 Email 推送

> **🔒 安全性改進**：
> - 敏感值已遷移至 GCP Secret Manager，`gcloud run jobs describe` 只顯示 secret 參照路徑，不再明文顯示密碼
> - `.env` 仍加入 `.gitignore`，**絕對不要 commit**
> - 檢查 Secret 是否正確注入：
>   ```bash
>   # 查看 secret 參照（不顯示明文值）
>   gcloud run jobs describe stock-report --region=asia-east1 \
>       --format="yaml(spec.template.spec.containers[0].env)"
>   ```

## Step 3：部署 Pipeline（Cloud Run Jobs）

系統拆為兩個獨立 Job，共用同一個 Docker image：

| Job | CMD | 用途 | 資源 | Timeout |
|-----|-----|------|------|---------|
| `stock-data` | `--daily-data` | 價格 + 籌碼 + 估值面抓取 | 1Gi / 1 CPU | 600s |
| `stock-report` | `--daily-report` | 選股報告 + Email 推送 | 2Gi / 2 CPU | 1800s |

拆分的好處：
- 資料抓取失敗不影響報告（可用前一天資料）
- 報告可獨立重跑（不需重新抓資料）
- 兩個 Job 的 timeout / 資源可獨立配置

```bash
bash deploy/deploy-pipeline.sh
```

腳本會：
1. 用 `docker buildx build --platform linux/amd64` 交叉建置映像
2. 推送至 Artifact Registry
3. 產生 YAML 環境變數檔（自動處理特殊字元）
4. 部署 `stock-data` Job（1Gi, 1 CPU, timeout 600s）
5. 部署 `stock-report` Job（2Gi, 2 CPU, timeout 1800s）

### stock-data 執行流程（`--daily-data`）

```
DailyUpdater.run()
    │
    ├─ 1. 批量查詢當日價格（FinMind taiwan_stock_daily）
    │     └─ 無資料 → 非交易日，return False，跳過後續
    │
    ├─ 2. 批量查詢 6 個籌碼 dataset
    │
    └─ 3. 批量查詢估值面（stock_per + market_value）
```

### stock-report 執行流程（`--daily-report`）

```
run_daily_report()
    │
    ├─ scan_stocks() → 多策略掃描全市場
    ├─ build_report() → 產出 reports/daily_pick_YYYY-MM-DD.md
    └─ send_report_email() → Gmail SMTP 推送報告
        └─ 環境變數缺失時靜默跳過
```

> **向後相容**：`--daily` 旗標仍可用，等同依序執行 `--daily-data` + `--daily-report`，非交易日自動跳過報告。

## Step 5：設定每日排程

```bash
bash deploy/setup-scheduler.sh
```

腳本會自動偵測專案的 default compute service account 來設定 OAuth 認證。

排程設定：

| 排程名稱 | Cron (UTC) | 台北時間 | 觸發 Job |
|----------|-----------|---------|----------|
| `trigger-stock-data` | `30 10 * * 1-5` | 18:30 週一至五 | `stock-data` |
| `trigger-stock-report` | `40 10 * * 1-5` | 18:40 週一至五 | `stock-report` |

> 報告排程延遲 10 分鐘，等資料抓取完成後再執行。資料抓取通常 < 1 分鐘，10 分鐘留有充裕緩衝。

### 手動操作排程

```bash
# 手動觸發
gcloud scheduler jobs run trigger-stock-data \
    --location=asia-east1 --project=stock-analysis-tw
gcloud scheduler jobs run trigger-stock-report \
    --location=asia-east1 --project=stock-analysis-tw

# 暫停排程
gcloud scheduler jobs pause trigger-stock-data \
    --location=asia-east1 --project=stock-analysis-tw
gcloud scheduler jobs pause trigger-stock-report \
    --location=asia-east1 --project=stock-analysis-tw

# 恢復排程
gcloud scheduler jobs resume trigger-stock-data \
    --location=asia-east1 --project=stock-analysis-tw
gcloud scheduler jobs resume trigger-stock-report \
    --location=asia-east1 --project=stock-analysis-tw
```

## 踩坑紀錄

### 1. gcloud 安裝 Python 版本衝突

**問題**: `brew install --cask google-cloud-sdk` 在 macOS 13 失敗，報 `python path does not exist`。
**原因**: Homebrew 的 gcloud cask 預設找 `python@3.13`，但 Homebrew 在 macOS 13 沒安裝它。
**解法**: 用官方 tarball + 指定 `CLOUDSDK_PYTHON=/opt/homebrew/opt/python@3.10/libexec/bin/python3`。

### 2. Docker Desktop 版本不相容

**問題**: `brew install --cask docker` 報 `does not run on macOS versions older than Sonoma`。
**原因**: Docker Desktop 4.64+ 要求 macOS 14 (Sonoma) 以上。
**解法**: 手動下載 Docker Desktop 4.30（build 149282），這是最後支援 Ventura 的版本。

### 3. Cloud Run exec format error

**問題**: 部署後容器啟動失敗，log 顯示 `exec format error`。
**原因**: Apple Silicon Mac 預設 build 出 `arm64` 映像，Cloud Run 需要 `amd64`。
**解法**: 用 `docker buildx build --platform linux/amd64` 交叉建置。

### 4. --set-env-vars 特殊字元解析錯誤

**問題**: `gcloud run jobs create --set-env-vars` 解析 email 地址的 `@` 時報 `Bad syntax for dict arg`。
**原因**: gcloud 把 `@` 和 `,` 視為分隔符。
**解法**: 改用 `--env-vars-file` 傳入 YAML 檔，值用雙引號包裹。

### 5. EMAIL_APP_PASSWORD 被 shell 截斷

**問題**: Cloud Run 環境變數中 `EMAIL_APP_PASSWORD` 被截斷為第一段（應為完整 16 字元），Email 登入失敗。
**原因**: `export EMAIL_APP_PASSWORD=xxxx xxxx xxxx xxxx` 不加引號，shell 把空格後的部分視為獨立指令。
**解法**: `export EMAIL_APP_PASSWORD="xxxx xxxx xxxx xxxx"` 加雙引號。部署腳本的 YAML 也用雙引號包裹。

### 6. 非交易日 Cloud Run Job timeout

**問題**: 週末或假日觸發 Job 後，`DailyUpdater` 秒結束但 `run_daily_pick()` 掃描全市場耗時 1 小時直到 timeout。
**原因**: 原本資料抓取和報告綁在同一個 Job，非交易日仍會觸發報告。
**解法**: 拆為 `stock-data` + `stock-report` 兩個獨立 Job。`stock-data` 在非交易日秒結束；`stock-report` 獨立觸發，即使非交易日也能用前一天的資料產報告（或選擇不觸發）。

### 7. gcloud --args 逗號分割問題

**問題**: `gcloud run jobs update --args` 傳入含逗號的 Python 指令時，被 gcloud 分割成多個 args。
**原因**: gcloud 用逗號作為 `--args` 的分隔符。例如 `--args="run,python,-c,import sys, smtplib"` 會把 `smtplib` 當獨立 arg。
**解法**: 不要在 `--args` 中放含逗號的 Python 程式碼，改用獨立腳本檔（如 `scripts/test_email.py`）。

### 8. Cloud Logging 抓不到 stdout

**問題**: Cloud Run Job 的 `print()` 輸出在 Cloud Logging 中看不到，只顯示 exit code。
**原因**: Cloud Run 的 stdout 在某些情況下不會立即 flush 到 Cloud Logging。
**解法**: 使用 `print(..., file=sys.stderr)` 輸出到 stderr，Cloud Logging 可靠捕獲。或在腳本開頭設定 `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, write_through=True)`。

### 9. Cloud Scheduler 找不到 Service Account

**問題**: `setup-scheduler.sh` 建立排程失敗，報 `NOT_FOUND: Requested entity was not found`。
**原因**: 腳本硬編碼 `${PROJECT_ID}@appspot.gserviceaccount.com`（App Engine default SA），但專案未啟用 App Engine，該 SA 不存在。
**解法**: 改用 default compute service account（`XXXXXX-compute@developer.gserviceaccount.com`）。腳本已修正為自動偵測。

### 10. export xargs 截斷含空格的 .env 值

**問題**: 部署後 `EMAIL_APP_PASSWORD` 只有 4 字元（應為 19 字元），Gmail SMTP 驗證失敗（535 BadCredentials）。
**原因**: `export $(grep -v '^#' .env | grep '=' | xargs)` 在 `EMAIL_APP_PASSWORD=hcyj uhor fhpq uwwe` 處，`xargs` 把空格後的 token 當作獨立參數，只有 `EMAIL_APP_PASSWORD=hcyj` 被 export。
**解法**: 改用 `while IFS='=' read` 逐行載入（見 Step 2），或手動 `export EMAIL_APP_PASSWORD="完整密碼"`。

### 11. EMAIL_PROXY 帶入 Cloud Run 造成連線失敗

**問題**: Cloud Run 容器連線 Gmail SMTP 時走了不存在的本地 proxy，導致連線超時。
**原因**: `.env` 中有 `EMAIL_PROXY=http://127.0.0.1:7890`（本地開發用），被 `deploy-pipeline.sh` 帶入 Cloud Run 環境。
**解法**: 部署腳本已移除 `EMAIL_PROXY` 寫入邏輯。載入 `.env` 時也要 `unset EMAIL_PROXY`。

### 12. gcloud run jobs describe 明文洩漏密碼（已解決）

**問題**: `gcloud run jobs describe` 會明文顯示所有環境變數，包括資料庫密碼、API Token、Email 密碼。
**風險**: 在螢幕分享、CI/CD log、終端機紀錄中可能洩漏機敏資訊。
**解法**: 已遷移至 GCP Secret Manager。`gcloud run jobs describe` 現在只顯示 secret 參照路徑（如 `supabase-url:latest`），不再明文顯示密碼。
