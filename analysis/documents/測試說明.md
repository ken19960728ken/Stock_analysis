# 測試說明文檔

## 概覽

本專案使用 **pytest** 作為測試框架，共 15 個測試模組、**296 個測試案例**，覆蓋資料撈取（Scanner）、量化策略、回測引擎、因子分析、組合最佳化、事件研究、機器學習等完整功能。

## 執行方式

```bash
# 執行全部測試
uv run pytest tests/ -v

# 執行單一模組
uv run pytest tests/test_all_strategies.py -v

# 執行特定測試類別
uv run pytest tests/test_all_strategies.py::TestMACrossStrategy -v

# 執行特定測試
uv run pytest tests/test_all_strategies.py::TestMACrossStrategy::test_basic_signal_generation -v

# FinMind API 診斷（需標記 -m api，預設跳過）
uv run pytest tests/test_finmind_api_diagnostic.py -m api -v
```

## 測試設計原則

### 1. 無外部依賴

所有測試使用 Mock，不需要：
- 資料庫連線（Supabase）
- 外部 API（FinMind / Yahoo Finance）
- 網路連線

### 2. 確定性

- 需要隨機資料時固定 `np.random.seed()`
- 時間序列使用 `pd.date_range()` 生成固定日期

### 3. 策略測試三原則

每個策略至少測試：

1. **基本訊號產生**：`generate_signals()` 回傳含 `signal` 欄位的 DataFrame，值為 {-1, 0, 1}
2. **參數修改**：`set_params()` 正確更新內部參數，修改後仍可正常執行
3. **邊界條件**：缺少欄位、資料量不足時 graceful degradation（回傳全 0 signal）

### 4. 進階測試模式

| 模式 | 說明 | 範例 |
|------|------|------|
| 趨勢觸發 | 構造特定趨勢觸發買/賣 | MA 金叉/死叉 |
| 參數敏感度 | 比較不同參數的訊號數量 | Bollinger std_dev 大小 |
| 極端情境 | 平坦/暴跌/暴漲資料 | RSI 超買超賣 |
| 資料注入 | 預注入結果直接返回 | EventDriven signal passthrough |

## 常見問題

### Q: 測試跑不過怎麼辦？

```bash
# 看完整錯誤訊息
uv run pytest tests/test_xxx.py -v -s

# 只跑失敗的測試
uv run pytest tests/ --lf

# 看 fixtures 列表
uv run pytest tests/ --fixtures
```

### Q: 如何新增策略測試？

1. 在 `tests/test_all_strategies.py` 新增測試類別
2. 遵循命名規範：`TestXxxStrategy`
3. 至少包含 3 個測試：基本訊號、參數修改、邊界條件
4. 使用 `conftest.py` 中的共用 Fixture

### Q: FinMind API 診斷測試為什麼被跳過？

`test_finmind_api_diagnostic.py` 需要真實 API Token，標記為 `@pytest.mark.api`，預設跳過。執行方式：

```bash
uv run pytest tests/test_finmind_api_diagnostic.py -m api -v
```

### Q: 如何只測試策略相關？

```bash
# 所有策略測試（84 個）
uv run pytest tests/test_all_strategies.py tests/test_strategies.py -v

# 特定策略
uv run pytest tests/test_all_strategies.py::TestMACrossStrategy -v
```
